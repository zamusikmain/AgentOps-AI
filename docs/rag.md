## Реализованная архитектура

1. `POST /api/knowledge/documents?name=...`: двоичная загрузка PDF; лимит 5 МиБ, проверка расширения и сигнатуры. Frontend proxy читает файл порциями и отклоняет превышение лимита. Файл хранится только по серверному UUID, не по пользовательскому пути.
2. Фоновое извлечение через установленный `pypdf 6.20.0` в отдельном фиксированном Python-процессе. Процесс не получает ключи и секреты окружения. Нет выполнения PDF JavaScript, переходов по ссылкам или запуска произвольного кода. Таймаут 20 секунд, до 100 страниц, до 500 000 извлечённых символов, до 4 МБ вывода процесса. Зашифрованные, повреждённые PDF и сканы без текста получают сохранённую безопасную ошибку.
3. Chunking внутри каждой страницы: до 1000 символов с перекрытием 160 символов; исходный текст не меняется в архиве. В SQLite сохранены документ, SHA, статус, страницы, фрагменты и частоты терминов. Максимум 100 документов, агенту назначается максимум 50.
4. Локальный лексический поиск с IDF и нормализацией терминов RU/EN, возвращает максимум 5 фрагментов с документом, страницей и ID. Встроенные тестовые документы оставлены для совместимости прежних агентов; они не смешиваются с выделенным PDF RAG-сценарием.
5. Каждый агент получает явные `document_ids` и разрешение `knowledge_search`. Knowledge Search проверяет выбранные ID против разрешённого набора, включая повторно используемый результат. Single-Agent и Multi-Agent передают разрешения в общий Tool Executor. Нельзя передать произвольный путь или расширить список документов аргументами модели.
6. `POST /api/knowledge/ask`: создаёт обычную задачу и запуск, принудительно выполняет разрешённый Knowledge Search, затем один шаг модели через существующий LangGraph Runner. Не более одного LLM-вызова, до 2048 выходных токенов, общий таймаут исполнения, без автоматических повторов и переходов на другой провайдер. Поиск в Tool Executor вынесен в поток, чтобы соблюдался его таймаут.
7. Google GenAI adapter подключён через существующий `response_json_schema`. Модель выбирает `{found, citations:[{chunk_id, quote}]}`. Backend проверяет строгую схему, принадлежность фрагмента выдаче и разрешениям, страницу и имя документа, а также **точное наличие цитаты в оригинальном извлечённом тексте SQLite**. Итог содержит только проверенные цитаты; произвольный фактический текст модели не принимается. Отсутствие ответа имеет отдельный RU/EN текст.
8. Модель в выделенном RAG-шаге не получает никаких инструментов. Найденные инструкции считаются данными, подозрительные строки фильтруются из контекста; оригинал сохраняется. Инструкция PDF не может дать разрешение HTTP Fetch, shell или write. Обходы и ошибки сохраняются в истории.
9. Knowledge Base RU/EN: загрузка, индексируется/проиндексирован/ошибка, просмотр извлечённых страниц, удаление, выбор агента, явно помеченные Mock/Gemini режимы, ответ, цитаты и источник, токены, длительность, отмена, история инструмента и запусков. По умолчанию выбран Mock. Вручную выбранный Gemini потребует подтверждения отправки фрагментов, но в этой проверке он не использовался.
10. Удаление документа запрещено во время использующего его запуска. После удаления очищаются индекс, файл и разрешения агентов. Ранее сохранённые ответы и цитаты остаются в истории. Удаление проверено только на изолированных тестовых документах; рабочий предоставленный PDF сохранён.

## Ограничения и следующие шаги

- **Живой Gemini RAG не проверен:** отдельного разрешения не было. Проверены только SDK-контракт и Mock end-to-end. Доступность выбранной модели, квота, фактические токены и семантическое качество Gemini остаются для отдельно разрешённой проверки. Подход structured output сверялся с [официальной документацией Google](https://ai.google.dev/gemini-api/docs/structured-output).
- Это извлекающий RAG: ответ — точные цитаты, без свободного пересказа или сложного синтеза. Mock — общий алгоритм выбора строк по совпадению терминов, не семантическая модель; правильная цитата ещё не доказывает понимание произвольного вопроса.
- Лексический индекс без embeddings/reranker: синонимы, перевод запроса на другой язык и сложные вопросы могут пропускать информацию. Отсутствие в найденных фрагментах не является математическим доказательством отсутствия во всех документах. Для данного PDF отсутствие цены подтверждено явной строкой и проверкой всех трёх страниц.
- OCR, сложное восстановление таблиц/колонок, сканы, зашифрованные документы и нестандартные PDF не поддержаны. Ограничения текстового извлечения описаны в [документации pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html).
- Фильтр подозрительных строк эвристический, не универсальный детектор prompt injection. Основные жёсткие меры — отсутствие действий в RAG-шаге, проверка разрешений, строгая схема и точное сопоставление цитат. Живое поведение Gemini на вредоносном PDF не проверялось.
- PDF parser работает отдельным процессом с таймаутом и ограничением вывода, но без OS-лимита памяти. Для публичного размещения потребуется более строгая изоляция, защита от decompression bombs, антивирусная обработка и общий дисковый бюджет.
- Поиск читает разрешённые фрагменты и ранжирует их локально; для большой базы нужен полнотекстовый/векторный индекс и нагрузочные тесты. UI выбора агента показывает первые 100 агентов.
- Система остаётся локальным пространством с одним owner/admin Bearer-токеном. API просмотра документов предназначен этому владельцу; разрешения ограничивают агентов. Изоляции пользователей/tenant ACL нет. Разрешения запуска фиксируются в snapshot; изменение формы агента влияет на следующие запуски. MCP Search по-прежнему работает с встроенными документами, а загруженные PDF обслуживает встроенный Knowledge Search.
- После удаления документа сохранённые цитаты остаются в истории и checkpoint-базе. Полное стирание истории/секретов не является функцией удаления Knowledge Base.
- Фоновая индексация после перезапуска помечается failed, автоматического повтора нет. Повторная загрузка одинакового PDF создаёт отдельный документ.

`backend/.env` не изменён (сверены хеш до/после проверки и время изменения). Ключи не выводились, платные ресурсы не создавались, commit/push/deployment не выполнялись. Рабочие документы и прежняя история сохранены.
