## Обнаруженная ошибка и исправление

Во втором запросе Gemini корректно вернул «Срок хранения записей аудита - 400 календарных дней.», но в извлечённом PDF после слова «Срок» находится перевод строки. Первоначальная побайтовая проверка ошибочно считала замену перевода строки пробелом неподтверждённой цитатой. Ошибка **локальная** `invalid_rag_citation`, не ошибка HTTP/квоты Gemini. Ответ Gemini и реальные токены этой попытки сохранены в checkpoint SQLite; failed execution и события остаются в истории. Эта попытка засчитана в общий лимит.

Исправлен `backend/app/rag_answers.py`: допускается только различие пробельных символов между неизменными словами. Найденный исходный span возвращается буквально из текста PDF — итоговая цитата сохраняет оригинальный перевод строки. Нельзя менять слова, числа, единицы, пунктуацию, ID фрагмента или пропускать промежуточные слова. Дополнительная проверка оригинального текста/страницы/документа в SQLite сохранена. Пустые пробельные цитаты запрещены. Проверка не зависит от названия проекта, числовых ответов или содержания этого PDF.

Добавлены регрессионные тесты: восстановление исходной цитаты с переводом строки и отказ при замене чисел, единиц, пунктуации, пропуске слов и пустой цитате. После регрессии выполнен один ручной повтор вопроса об аудите; он completed. Ещё три вопроса выполнены по одному разу. Других ошибок генерации, недоступности модели или квоты не было.

## Поиск, контекст и отсутствие выдуманных источников

Для каждого запуска прочитан реальный LangGraph checkpoint. Первый user message, переданный узлу модели, содержит JSON с вопросом и найденными фрагментами. Проверено его точное равенство сохранённой выдаче ToolCall. ID совпали с `rag_retrieved.chunks`. Порядок событий проверен: `tool_completed` → `rag_retrieved` → `model_requested` → `model_completed`. В отчёте JSON сохранены хеш контекста, ID всех переданных фрагментов и исходный структурированный ответ модели. Проверочный скрипт не подставляет ожидаемые ответы и не вызывает Mock Provider.

Сами цитаты успешных запусков дополнительно сверены прямыми SELECT из `knowledge_chunks`: оригинальный текст содержит точную итоговую цитату, страница и document_id совпадают. Результат и provider snapshot сверены с `executions`; вопросы хранятся в задачах/snapshot; события — в `execution_events`; поиск — в `tool_calls`; переданный контекст и исходный ответ модели — в отдельной checkpoint SQLite. Failed попытка сохранена, не заменена успешной задним числом.
