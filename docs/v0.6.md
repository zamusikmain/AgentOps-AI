# AgentOps AI v0.6 — RAG Evaluation & Answer Reliability

Дата: 11 октября 2026. Только локальный **Mock**, реальных Gemini generation/embedding API-запросов **0**. `.env` и ключ не изменялись. Commit, push, deployment отсутствуют.

## Реализовано

- `answer_verification.py`: разбиение извлечённого ответа на утверждения; отдельная проверка exact source span, doc/chunk/page, query anchors, числового значения/идентификатора/даты; conservative sufficiency и machine-readable refusal reasons. Статусы: supported, unsupported, insufficient_evidence, conflicting_evidence, not_applicable.
- Citation existence и answer sufficiency раздельны. RAG retrieval сохраняет SHA256 версии документа; проверка цитаты сравнивает его с текущей SQLite-версией, разрешениями, страницей, chunk и буквальным источником. Изменение чисел, единиц или ID блокируется прежним exact quote validator.
- Противоречия определяются общими key/value правилами в найденных источниках; несколько обязательных ключей в multi-hop вопросе требуют подтверждения всех ключей. Номера разделов сами по себе не являются числовым ответом.
- Новые RAG результаты содержат `verification`, safe_answer, claims, citation_checks, sufficiency, conflicts, refusal reason. Без достаточности UI отображает «В доступных документах недостаточно информации для ответа», не исходный непроверенный выбор модели. В history сохраняются результаты и события rag_verified / rag_verification_failed.
- `evaluation_metrics.py`: Hit@1/3/5, MRR, Recall@5, binary nDCG@5, latency; независимо answer/reference accuracy, citation validity, claim support, correct/false abstentions. Эталон не поступает в MockProvider.
- 40 версионированных случаев в `docs/fixtures/rag-evaluation-v1.json`: 10 exact, 10 paraphrased, 5 multi-hop, 5 unanswerable, 5 conflicting, 5 adversarial. Корпус: корпоративный **тестовый** PDF и 2 синтетических PDF по 5 страниц. Никаких реальных конфиденциальных данных.
- Bootstrap загружает только фиксированные известные fixtures и создаёт явно назначенного тестового агента. Evaluation источники связываются с trusted SHA256, не с произвольным именем файла. Каждая выборка проверяет текущие permissions; revoke/version change/deletion закрывают history/cases. Нельзя передать скрипт, путь или произвольный dataset через API.
- SQLite migration 006: evaluation_runs и evaluation_cases; dataset version, immutable reference snapshots, provider/model metadata, tokens, times, results. При рестарте прерванные evaluation помечаются failed; автоматического повтора нет.
- Dashboard «Оценка RAG»: сравнение метрик, история, пагинация 120 результатов, question/expected/actual, исходный diagnostic выбор, цитаты, найденные фрагменты и проверки. RU/EN через текущий i18n, темы и mobile.

## Ограничения запуска и API

`POST /api/evaluation/install` — только bundled fixtures. `POST /api/evaluation/runs` — agent_id, provider=mock. Один concurrent run, 40 вопросов × 3 режима, до 120 MockProvider calls, 2048 output tokens на ответ, 245760 output / 2000000 input budget (Mock estimates), общий timeout 120 секунд, retrieval timeout 8 секунд, result до 100 KB на случай, до 500 run histories. Документы сохраняют прежние upload/index ограничения.
GET runs/cases повторно проверяет scope и версии. Metadata списка не включает passage content; детали доступны только при действующих разрешениях исходного агента. Cancel сохраняет статус и уже выполненные случаи. API и frontend proxy защищены прежним owner token/origin policy.
`GET /api/evaluation/live-preflight` документирует модели, план лимитов, данные и отдельное согласие на отправку PDF. provider=live **отклоняется 403 evaluation_live_disabled**, даже при переданном consent. Исполняемый live benchmark не добавлен: сначала нужны отдельное разрешение человека, проверка Free Tier/моделей и меньший согласованный бюджет. Стоимость не предполагается нулевой и не вычисляется вымышленно.
Обратная совместимость: legacy `answer` и `found` остаются исходной extractive selection. Они **не означают verified**. Новые клиенты должны использовать `verification.safe_answer`, `verified`, `status`, `reason`. Старые сохранённые ответы без verification доступны как legacy history; проверки для них задним числом не выдумываются.

## Обнаруженные и исправленные проблемы

- При первом benchmark номер раздела `3` мог засчитаться как numeric evidence; заменено общей проверкой substantative value с единицей, датой или ID. Эталонные ответы не менялись.
- Reference string mismatch первоначально назывался unsupported answer. Разделены source support и reference mismatch; сохранён отдельный счётчик, mismatch не скрывается.
- Fixture identification по имени не переживало загрузку того же PDF под другим именем; binding заменён на trusted content SHA256.
- UI тест искал exact question на первой странице cases, хотя порядок был category-first; исправлен просмотр существующего случая. Старый agent navigation locator не учитывал счётчик агентов; исправлен.

## Известные ограничения / следующий этап

- Grounding — conservative deterministic heuristics, не полноценное semantic entailment. verified означает прохождение описанных проверок, **не математическую гарантию истины**. Сложные вопросы, даты, сравнения и перефразы часто получают false refusal. Нужен независимый набор validation/calibration, constrained claim extractor и semantic checking с human-reviewed evidence.
- Генерация остаётся extractive RagSelection, не свободный narrative ответ. Mock не исправлялся ответами из dataset. Citation validator запрещает выдуманные значения; генератор выбирает реальные цитаты, но недостаточно понимает перефразы.
- Conflict detector сравнивает синтаксические ключи/значения. Не реализованы temporal validity, authoritative source precedence, unit normalization или общий NLI; эквивалентные единицы могут выглядеть конфликтом, сложные противоречия могут быть пропущены.
- Evaluation только fixed bundled dataset. Не добавлены произвольный импорт dataset, LLM judge, execute-live endpoint, pgvector/ANN и multi-tenant authentication. Owner workspace однопользовательский; прав отдельных агентов достаточно для локального MVP, но не для публичного multi-user сервиса.
- SQLite O(N×dimension) поиск и thread timeouts сохраняют ограничения v0.5. Permission revoke блокирует дальнейшую выдачу результатов; worker уже начатого read-only запроса останавливается после завершения текущей операции. Предварительно открытый текст в памяти браузера невозможно «отозвать» мгновенно.
- Prompt injection фильтруется существующей эвристикой и tool permission boundaries; known adversarial/injection tests не доказывают защиту от всех атак. Требуются threat modelling и independent security tests.
- Для production: tenant RBAC, durable job queue, deletion/retention policy для history, calibrated abstention, wider multilingual datasets, latency/load testing, live Free Tier verification только с отдельным разрешением.
