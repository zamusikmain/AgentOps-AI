# AgentOps AI v0.2 — Multi-Agent Orchestration

Реализовано создание и редактирование процессов из 2–8 разных агентов. Шаблон: Planner → Researcher → Executor → Reviewer. Последний агент обязан иметь роль Reviewer. Последовательность исполняется настоящим LangGraph; каждый этап вызывает выбранный Provider с инструкциями своего агента и структурированным входом.

## Передача результатов

Вход каждого этапа содержит `task`, `artifacts` предыдущих этапов и `review_feedback`. Выход проверяется Pydantic: `{summary, data}`; Reviewer добавляет `decision: approve | revise` и `feedback`. Невалидный ответ сохраняется как raw output и завершает запуск ошибкой, без скрытого повторного запроса.

При revise граф возвращается к настроенному этапу. Устаревшие результаты повторяемых этапов удаляются из активного контекста, но все попытки остаются в истории SQLite. Отзыв Reviewer передаётся повторяемым агентам. Исчерпание лимита ревизий завершает запуск явной ошибкой.

## Проверенный пример Mock

Задача: «Release a customer portal», инструкции: подготовить безопасный checklist запуска из предоставленного контекста. [Полный сохранённый пример](workflow-mock-example.json) создан через backend с отдельной временной SQLite; реальных Gemini-запросов: 0.

| Этап | Полученные результаты | Результат |
|---|---|---|
| Planner | Нет | Структурированный план с пометкой MOCK |
| Researcher | Planner | Структурированные данные и предыдущий результат |
| Executor | Planner, Researcher | Структурированный результат исполнения |
| Reviewer | Planner, Researcher, Executor | Структурированный review, approve |

Четыре вызова: 110 входных + 160 выходных = 270 токенов. Проверена точная передача JSON предыдущего ответа в следующий вход, длительности, история событий и чтение после повторного открытия SQLite. Mock является явным тестовым провайдером: его ответы генерируются из входного контекста. Оркестратор не содержит заранее подготовленного диалога агентов. Это проверка механики, а не качества LLM.

Отдельные тесты Reviewer revise проверяют шесть вызовов: Planner → Researcher → Executor → Reviewer → Executor → Reviewer, передачу замечания и сохранение обеих попыток.

## Лимиты и отмена

- 0–3 ревизии, до 64 вызовов на процесс; действуют также ограничения каждого агента.
- Общий бюджет 1024–262144 входных и выходных токенов; перед вызовом резервируется консервативная оценка входа, после вызова учитываются реальные метаданные, включая thinking.
- Таймаут 1–600 секунд, дополнительно ограниченный серверным таймаутом (по умолчанию 180 секунд).
- Single-Agent и workflows используют общий последовательный worker и очередь до 10 запусков.
- Отмена и ошибки на любом этапе сохраняются в SQLite. После перезапуска незавершённый запуск получает server_restarted; автоматического повторного Gemini-вызова нет.

Резерв входных токенов может остановить процесс раньше фактического исчерпания бюджета. Это ограничение выполнения, не гарантия стоимости. Уже отправленный запрос может расходовать квоту после отмены. Разрешены только калькулятор и UTC-время; сетевых и shell-инструментов у агентов нет.

## Хранение и интерфейс

Миграция 002 добавляет workflows, workflow_runs, workflow_steps и workflow_events, сохраняя существующие таблицы. Конфигурация запуска фиксируется snapshot. История включает вход, валидированный и сырой выход, ошибки, попытки, токены и длительности. LangGraph checkpoints остаются в отдельной SQLite.

Раздел «Процессы» / Workflows позволяет настроить порядок агентов и лимиты, запустить задачу, просмотреть граф, текущий этап, результат, входы/выходы и события, отменить выполнение. Все новые экраны и сообщения поддерживают RU/EN. История workflows отделена от Single-Agent задач; Dashboard суммирует оба режима.

API: CRUD `/api/workflows`, запуск `/api/workflows/{id}/run`, список/детали `/api/workflow-runs`, `/steps`, `/events`, `/cancel`. Существующая авторизация и same-origin proxy применяются к новым маршрутам.

## Roadmap и границы

Пока доступен последовательный граф с циклом ревизии, без параллельных ветвей, произвольного DAG или визуального редактора связей. Researcher работает с переданным контекстом; поиск, RAG и реальный MCP transport — roadmap. Также остаются распределённая очередь, ручное продолжение checkpoints, RBAC, серверные approvals для инструментов с побочными эффектами, encryption и retention.

Реальный многоагентный Gemini-запуск не выполнялся: отдельного разрешения на него в v0.2 нет. Production PostgreSQL, Docker и несколько backend workers не проверялись. Локальные данные не шифруются. Single-Agent сохранён и покрыт регрессионными тестами.
