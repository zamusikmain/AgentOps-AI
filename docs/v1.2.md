# AgentOps AI v1.2 — Gemini integration and controlled Live readiness

Implementation uses the existing FastAPI/SQLAlchemy/SQLite application, LangGraph Runner, Reliability execution facade, RAG/evidence/citation pipeline and Google Gen AI SDK. No second execution engine was added. This is a local development application, not a production-ready service. New external AI calls in this delivery: **0**. Live quality, project quota and actual provider billing remain **UNVERIFIED**.

## Architecture and modes

`AI Workspace → session/Bearer auth → CSRF/RBAC → owner/tenant workspace check → durable grant → LangGraph → Reliability/circuit/concurrency/reservation → Gemini SDK → structured response → evidence/citation verification → SQLite → UI`.

`MOCK_ONLY` retains the original offline workspace and Mock indices. `REAL_DRY_RUN` reads scoped documents, counts chunks and planned calls, validates budgets and persists an exportable plan; it does not construct a Google client or index externally. `REAL_EXECUTION` has a real SDK dispatch route but requires the default-false `WORKSPACE_LIVE_ENABLED` server gate and a separate bounded administrator grant. The gate was not enabled in the working configuration. No `.env` changes were needed.

Endpoints under `/api/workspaces/{id}`: `dry-run`, `dry-runs`, `authorizations`, `authorizations/{grant}`, `live` (ask), `google/{grant}/reindex`, restricted Google history/source/trace/cancel routes, `smoke/prepare`, `smoke`, `smoke/{run}`, and cancellation. The existing offline proxy remains locked to Mock. Auth/provider/budget configuration routes are never forwarded through the Google gateway.

## Authorization and shared budget

Grants are durable `LLMConfiguration(kind=live_grant)` records, with administrator, tenant, workspace, dataset, exact document ID/SHA-256 map, selected models, requests, tokens, positive USD cap, expiry and revocation. Creating a grant requires an admin and an exact explicit confirmation phrase. The current user's active admin status is rechecked when it is a database user. The source map is rechecked at every dispatch. Frontend selection, API key possession and this document are not consent.

An atomic SQLite `BEGIN IMMEDIATE` reservation in the **parent ledger** covers both generation and embedding operations across child runtimes and parallel requests. Per-call monetary reservations also use the existing Reliability ledger. Integer nano-USD rounding prevents float boundary overspend. Attempts, retrieval embeddings, future retries/verification/fallback are subject to the same hook. The workspace policy currently fixes one generation attempt, no fallback and no LLM repair, so there is no hidden retry loop. Source text is never stored in the grant.

Input bounds use UTF-8 byte counts plus overhead; output budget includes thinking. Shared reservations are intentionally not refunded, even after reported usage, to retain a conservative upper bound. Reported input/output/thinking counts are recorded once. Missing embedding usage, cancellation and ambiguous timeout retain uncertain reservations. Token-derived estimated cost is distinct from actual provider invoice cost, which stays null. The grant closes on a reported token overrun; monetary overrun is also rejected by Reliability. Unknown/invalid pricing blocks dispatch.

## Embeddings and preservation

Google runs reuse `KnowledgeStore`/`VectorIndex` and `BudgetedGoogleEmbedding`, now wired into the workspace path. Namespace is a SHA-256 of tenant, owner, workspace, grant, model, dimension and revision. Google DB/checkpoints/PDF storage/cache are separate from offline Mock DB/vectors. Only explicitly authorized documents/chunks are copied, preserving IDs/pages/hash for citations. Runtime construction does not index. Explicit reindex or the separately authorized real smoke path builds vectors. Reindex validates the original PDF hash. Model signature, version parameters, cache key, dimensions and finite normalized values are enforced by the existing vector repository.

No new tables are required: existing `llm_configurations`, `llm_executions`, `budget_reservations`, execution/event and document/vector/cache tables are reused. Schema stays **009**, no migration 010 or destructive migration. A local excluded SQLite backup and row/hash preservation snapshot are taken; clean/upgrade migration regression tests remain part of the full suite. Existing users, sessions, documents, models, budgets, indices and evaluations are retained.

## Synthetic dataset and smoke runner

The requested display name `GeminiLiveSmoke-v1` already existed with an immutable five-document/twelve-question corpus. It is preserved unchanged. The new explicit namespace **`GeminiLiveSmoke-v1:v12`**, version `v12-3docs-10q`, has three policies, ten questions (5 RU/5 EN), precise/paraphrase/absent/conflict/access cases and expected evidence/pages/abstention/evaluation criteria. JSON and a checksum sidecar live in `docs/fixtures/gemini-live-smoke-v12.*`. The restricted Change policy is indexed but never assigned to access-test questions. An injection sentinel tests that source instructions remain data. Expected answers are read only by the post-generation evaluator, never sent to the model.

Runner preparation uses the existing PDF ingestion and Mock indexing. Dry Run persists a plan and no SDK requests. Mock execution creates actual agents/tasks, invokes `/knowledge/ask`, waits for existing Runner results and records execution IDs, per-case citations, token counts, duration and scoring. The real route is implemented behind the same exact dataset/data grant, explicitly indexes Google and uses the same ask route. Error, timeout, cancellation or exhausted grant stops it. Stop cancels an active child execution; records/export remain available in SQLite. Real runner quality remains unverified.

For the five short page chunks of this synthetic fixture: upper bound normally **45 calls** (5 document embeddings + 30 query embeddings + 10 generations), 150,000 reserved total tokens, 512 output tokens per generation, no retry/fallback and a 120-second runner deadline. The actual plan is calculated from extracted chunks. A simple conservative maximum is **$0.375** (all reserved tokens valued at the highest selected token rate), not a predicted invoice. Grant defaults (64 calls/$0.40) cover this plan; smaller caps fail readiness or dispatch. Query retrieval can use fewer calls; no fixed live count is claimed.

## Verification and limitations

Final measured results are recorded below after all checks finish. Automated provider/embedding tests are fixtures only. No Google request, external indexing, deployment or billing activation is performed.

Known limits: conservative UTF-8 estimates are not an official tokenizer; embedding SDK usage is unavailable to this adapter, so reservations remain uncertain. The documented model snapshot can age. Google project access and Free Tier quota need separate verification. SQLite and in-process child runtimes are intended for a local single-process service; there is no distributed job scheduler or runtime eviction. A grant gets its own vector/cache namespace, avoiding ambiguous sharing but duplicating storage across grants. Smoke scoring is deterministic and intentionally strict, not a substitute for human review. Live workspace UI does not prove provider readiness from a key or from a locally issued grant. No production-readiness claim is made.

See [future approval template](v1.2-live-approval.md) for remaining human approval and provider-account checks.

## Issues found and corrected during verification

- A batch evaluation hit the inherited single-run 180-second deadline after 191 of 192 cases. Batch evaluation now has its own configurable, bounded `EVALUATION_TIMEOUT_SECONDS` (default/max 300); Single-Agent and the 120-second Live smoke limits are unchanged. The repeated batch completed all 192 cases in 215.629 seconds under concurrent local test load. Gold/reference answers were not changed.
- Long local dataset preparation could exceed the generic 65-second frontend proxy timeout and leave the old agent selected after an aborted response. Only fixed, allowlisted preparation routes now have a bounded 300-second timeout. E2E waits for the actual successful preparation response and newly selected workspace before proceeding.
- The legacy external-embedding guard initially omitted adapter introspection properties. `client` and `requests` are delegated read-only; denied calls still construct no client. Default legacy real APIs are now closed even if environment flags are toggled. The old contract path accepts only explicitly marked in-process Mock/HTTP MockTransport fixtures; a fixture flag alone never authorizes a network SDK client. Controlled real RAG runs use the bounded workspace grant instead.
- Configured credentials and recognizable key/private-key/Bearer patterns are rejected in Gemini and embedding payloads before SDK dispatch. Tool output masking remains in place. SDK fixture tests prove the sensitive input cannot construct an SDK client. Embedding errors retain safe HTTP status/category metadata.
- The new synthetic security appendix is isolated from useful policy facts; the five page chunks yield a 45-call planning upper bound. The pre-existing Gold corpora and legacy smoke corpus are preserved. Byte-preserving Git attributes prevent checksum drift across Windows/Linux checkouts.
- Playwright's bundled Chromium was absent on this workstation. Tests use the already installed Edge through `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, with a disposable headless profile, not the user's browser profile.
